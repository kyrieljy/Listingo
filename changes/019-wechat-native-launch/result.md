# 验证记录

## 实现

套餐/补豆包 Native 支付、商户请求签名、微信公钥验签、AES-GCM 回调解密、事务权益、补偿查单、超时关单、退款登记和生产部署材料已实现。原路径开发，保留 tmp_test_recovery。商品下架仅影响新购买，不使已经付款开通的订阅失效。

额外处理了上线直接相关的问题：生产管理员手机号配置、真实短信初始化、禁止调试验证码、限制代理信任、隔离公开文件目录、停止跟踪测试产物和历史运行时加密密钥。回归发现敏感词匹配预先计算拼音导致原有50ms性能断言失败，改为按需构建视图，保持匹配逻辑。

## 验证范围与结果

- 完整后端首轮：351 项，347 通过、4 失败。原因是两个测试依赖未提交环境文件、模拟支付 Redis 锁兼容、原有敏感词性能断言。
- 上述失败项修复后，配置/Redis/敏感词及其集成与批量导入复测：40 项全部通过，未放宽性能断言。
- 最终支付专项：18 项，覆盖请求签名、响应/通知验签、解密、金额身份校验、快照、重复到账、并发、回滚、查单关单竞争、延迟通知、退款权限、生产防护及订单越权。
- 最终支付与既有商业计费联合复测：24 项，含32字符订单号限制、商品下架后已支付订阅仍有效及订单收据快照。
- 限流与支付联合复测曾完成32项通过；后续新增生产与快照校验纳入支付专项。
- 前端：8 个测试文件，106 项通过；TypeScript 检查与 Vite 生产构建通过。构建仍有既有大文件体积提示。
- Bash 语法、Compose 配置、Python 编译、git diff --check 通过。
- 浏览器：Browser plugin 不可用，使用已安装的 Playwright/Chromium；临时验证页挂载实际 PaymentModal、Ant Design 二维码和 Pinia，支付网络用本地测试响应替代。已验证1280×900与390×844布局、二维码画布、支付状态刷新、关闭窗口；无相关控制台错误，临时页面已删除。
- 数据库使用任务专用 PostgreSQL 16.15、独立测试库；已通过迁移 upgrade/downgrade/upgrade 验证。没有连接生产数据库。

全量首轮完成后仅对修复和新增部分复测，未把多次执行结果描述为一次全量全绿。
